Il self-test dichiarato contiene un caso positivo con rapporto plain, descriptor/payload gzip, stato di processo non riuscito, file binario e file nascosto, più 23 casi negativi: digest, dimensione, file mancante, file nascosto extra, path assoluto/escape, duplicato, symlink di file/directory, quattro metadati di processo discordanti, processo duplicato, pending/entry del catalogo, schema dell'indice, budget plain/gzip, READ-EVAL e forma aggiuntiva nell'indice e nel rapporto. Ogni processo figlio deve avere exit, classificazione e reason attesi; il marker del tentativo READ-EVAL deve restare assente. Directory e log sono nuovi con rifiuto di sovrascrittura. Questo elenco descrive casi scritti, non casi eseguiti dal revisore; non copre ogni possibile forma malformata o ogni confine dei budget.

Il limite C4 rilevato è che DIRECTORY materializza l'elenco di una directory prima del controllo incrementale delle 100000 voci: il contatore non limita preventivamente memoria o lavoro di enumerazione. Il sorgente finale lo dichiara senza modificare il traversal; nessun bounded preprocessing è rivendicato. Anche il self-test attende i processi figli senza timeout locale: controllo temporale esterno e gestione di una campagna bloccata restano responsabilità di chi la avvia. Mancano casi negativi dedicati ai confini 100000/100001 voci, 128/129 livelli, symlink pendente e limite espanso. Questi limiti non sono risultati di prodotto né difetti di integrità osservati su dati reali.
